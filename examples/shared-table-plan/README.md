# Shared setup, per-variant diamond, final join

This deliberately non-topological graph puts `final` before its prerequisites.
The explicit selection repeats `left`, `right` and `rowjoin` for compact and
wide variants. `setup`, `audit` and `final` remain once, yielding nine work items.
Each row has its own diamond join, and the final shared step waits on both rows.

Copy this example to an isolated workspace. Also copy
`../table-plan/capability-source-bundle.json` there: it is the existing canonical
synthetic MoonMold contract used by these operations. Compile it locally:

```sh
"$MOONFLOW_CLI" compile-capability-catalog "$WORKSPACE/capability-source-bundle.json" > "$WORKSPACE/catalog.json"
```

Follow [shared table planning](../../docs/SHARED_TABLE_PLANS.md) to preview and
save the v2 form, then import, inspect and prepare it with native MoonFlow.
The sample's health is deliberately valid at `2026-07-31T00:00:00Z`; it is not
current readiness evidence. Request files are synthetic digital-only planning
inputs, supplied rather than generated by the client. No example command
executes an adapter. Domain payload execution remains unqualified.
