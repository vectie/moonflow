# MoonFlow cross-product orchestration qualification

MoonFlow has no standalone user application. Its integrated qualification is
observed through MoonDesk and the participating product UIs while MoonFlow
retains the correlated run and receipts underneath them.

## Ordinary success path

1. A MoonBook declaration supplies the exact revision, digest, acceptance
   criteria, dependencies, and product-owned operation bindings.
2. MoonDesk imports and displays that graph without inventing operation IDs.
3. MoonFlow compiles installed manifests, adapter declarations, and fresh
   health evidence, rejecting schema, authority, version, or claim drift.
4. MoonGate returns the least authority and provider decision required by the
   next operation.
5. MoonClaw executes bounded agent work or the declared product adapter performs
   its own effect. MoonFlow records one attempt and idempotency identity.
6. The receiving product displays the result and returns an exact artifact and
   result receipt. Adapter success advances only to review.
7. A named reviewer accepts or rejects the exact output against the original
   criteria. MoonBook or Bookkeeper owns the accepted learning record.
8. MoonDesk shows the terminal result using the same run and receipt identities.

## Denial and recovery path

- Expired health, unknown operations, schema drift, insufficient authority, or
  an excessive claim ceiling stops before an attempt starts.
- An unknown external outcome reconciles by its original external job and
  idempotency identity before any retry.
- After stopping and restarting MoonFlow over the same durable root, MoonDesk
  reopens the same run position; an already retained receiver receipt
  reconciles instead of starting attempt two.
- Rejected quality creates revised input or a child run. It never rewrites the
  accepted parent history.

## Evidence record

Retain the MoonBook source digest, compiled capability catalog, MoonGate
decision, MoonFlow run/attempt/idempotency IDs, product result digest,
independent review receipt, restart observation, and the receiver's durable
return status. A rendered canvas or fixture-only adapter success is not an
integrated pass.
